# 🏢 Claw-Empire E2E "완전 자율형 나만의 에이전트 컴퍼니" 로드맵 및 식별 지표

> **작성 목적:** Telegram CEO 지시 발동부터 Agent 칸반 분업, Github 자동 Commit/Push, 그리고 최종 MD 보고서 회신까지 "사람의 개입이 0%인 무인 소프트웨어 회사"를 완성하기 위해 향후 최적화/구현해야 할 사항들을 식별합니다.

---

## 1. 현재 달성된 단계 (Current State)
* **API 및 칸반 트리거 체계:** CEO가 `$ (명령)` 또는 `# (태스크)`로 지시하면 큐에 담기고 실시간으로 프론트엔드 대시보드(Agent Office)에 칸반 보드로 시각화됨.
* **모델 라우팅 및 Staffing:** `AgentSelectModels.md` 규칙에 따라 작업 난이도를 판단하여 Pro/Flash 모델을 선별 적용할 구조적 기반 마련됨.
* **REST 연동 및 수동 개입:** UI 단에서 `▶️` 실행 버튼이나 오버레이 설정을 통해 통제 가능.

---

## 2. '완전 자동화 컴퍼니' 완성을 위한 식별 사항 (Missing Pieces)

### Step 1: Telegram Webhook ↔ PM Agent 텔레파시 파이프라인 (Trigger & Handoff)
* **식별 내용:** 현재 CEO가 텔레그램으로 메신저 봇에게 텍스트를 던졌을 때, 이를 폴링(Polling)하거나 웹훅(Webhook)으로 받아 `127.0.0.1:8790/api/inbox`로 밀어넣는 "중개 서버 로직(Bot Gateway)"이 필요합니다.
* **구현 목표:**
  * 봇 서버가 텔레그램 메시지를 수신하면, 내용 분석 전 일단 API에 POST 연동.
  * 봇이 "✅ 기획팀장(PM)에게 업무를 이관했습니다" 라고 1차 자동 응답.

### Step 2: 연쇄 소환 및 병렬 Worktree 체제 확립 (Cascade Sub-agenting)
* **식별 내용:** PM 에이전트가 `todo.md`를 기획한 후 멈춰있는 한계를 극복해야 합니다.
* **구현 목표:**
  * PM 에이전트에게 `/api/tasks/{new_id}`를 자체적으로 생성(Spawn)할 수 있는 MCP(Model Context Protocol) 툴 권한 부여.
  * 각 Sub-agent 호출 시, 기존 코드가 꼬이지 않도록 임시 `git worktree` 폴더를 할당하여 격리된 공간에서 작업 수행 후 본 브랜치에 Merge 시키는 백엔드 격리 샌드박스 연동.

### Step 3: 자율 빌드 검증 및 깃헙(GitHub) 자동화 (Auto QA & Push)
* **식별 내용:** 에이전트가 코드를 다 짜고 나서 사람이 수동으로 `npm run test` 하거나 `git commit/push` 하는 부분의 자동화.
* **구현 목표:**
  * QA 에이전트 노드 신설: 모든 서브 작업이 끝나면 최종 통합 브랜치에서 `tsc --noEmit` 등 테스트 스크립트 강제 실행 도구 연동.
  * 성공 시: 에이전트가 `git add .`, 작업 요약 컨텍스트를 반영한 `git commit -m "agent: ..."`, 그리고 `git push origin main` 명령어까지 OS 터미널 제어로 직접 날림.

### Step 4: CEO 실시간 Reporting (Markdown / Telegram 회신)
* **식별 내용:** 깃허브 푸시까지 마치면, 결과물이 어떤 로직으로 구현되었는지 `CEO_Report.md` 형태의 마크다운으로 추출하여 텔레그램으로 쏘아주는 종착점.
* **구현 목표:**
  * PM 에이전트 마지막 태스크로 "통합 산출물 보고서(report.md) 생성" 업무 지정.
  * 보고서 생성이 끝나면 봇 서버가 파일 시스템에서 해당 MD를 읽어, CEO의 텔레그램 채팅창에 "✅ 팀장 보고: 지시하신 기능의 배포가 완료되었습니다." 라는 알림과 함께 긴 문서(혹은 마크다운)로 전송.

---

## 3. 요약 및 CEO 권고사항
위 4가지 스텝만 파이프라인에 연결되면, 대표님은 **해변에 누워서 텔레그램으로 "회원가입 페이지에 모달창 하나 달아" 라고 텍스트 한 줄만 보내면, 회사(에이전트)가 알아서 PM 기획 -> 개발 -> QA -> GitHub 배포 -> 텔레그램 결과 보고서 전송까지 마치는** 진정한 **나만의 에이전트 컴퍼니**를 소유하게 됩니다.

현재 `main` 브랜치에 방금 셋업한 칸반 UI와 기능들이 모두 최신화 푸시되었으므로, 차기 스프린트로는 **'Step 1 & Step 2 (텔레그램 인제스트 & 에이전트 연쇄 소환)'** 백엔드 연결 작업부터 점진적으로 개발하실 것을 강력히 권장합니다.
